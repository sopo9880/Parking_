# Initial-occupied departure research — experimental only

This branch leaves SAFE and the production release unchanged. `initial_occupied_candidate.py` compares a current slot crop to its operator-supplied initial OCCUPIED image. A similar image can provisionally protect occupancy. An exploratory EMPTY proposal requires a recent outward movement of the same track plus a sustained, stable appearance change and no strong current FULL/AUX detection or conflicting camera view. Unresolved cases become UNKNOWN. An existing EMPTY state is not changed to OCCUPIED by appearance alone; later baseline entry may produce OCCUPIED.

This is not a validated vacancy or floor-visibility detector. It is sensitive to occlusion, camera movement, lighting, other moving vehicles, track switches, and overly persistent occupied references. Thresholds were set after reviewing G018/G021; they are hypotheses, not a pre-registered or independent test. Positive observations from another view veto a proposed EMPTY; missing linked local views cause an error. No GT is consumed by the state policy. G021 is a previously examined user-reviewed example, not a final holdout.

`run_initial_visual_experiment.py` reuses completed human-init GPU observations while reading the actual video at each saved timestamp. It records candidate states, per-view features, GT count bounds, and hashes. `run_initial_visual_dev.py` explores 330–660 and 660–900, using only prior AI pseudo snapshots; the candidate configuration is fixed before those DEV runs, but the same video and the diagnostic examples were already reviewed. UNKNOWN is retained in count bounds; ordinary Exact/MAE are omitted for a scope containing unknowns.

For human review, `select_transition_cases.py` selects a small set of DEV transitions and movement proposals without reading GT. `transition_review_ui.py` displays the global/local location, full CCTV and zoomed footage, permits timeline playback, and stores only explicitly selected human labels. `--extras-only` selects separate cases for long UNKNOWN and cross-camera detection disagreement; it must use a separate case and review file so completed cases are not asked again. In the prepared local environment, use `전이사례_검토_시작.cmd` for the first batch or `추가전이_검토_시작.cmd` for the separate extra batch. Replaying a clip at one-second steps does not establish its exact event time.

`analyze_reviewed_events.py` checks user-review and video hashes and summarizes candidate states within each reviewed clip. A parked-throughout clip can identify a false EMPTY proposal. A departure label applies to the interval and does not automatically create an exact departure time or a delay. A later occupancy prediction is not asserted to be a true re-entry without another human label. The review files, images, video, GT, and user snapshots stay local.
